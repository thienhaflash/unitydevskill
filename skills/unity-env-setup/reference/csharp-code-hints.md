# C# code hints in VS Code / Cursor (go to definition, IntelliSense)

An editor can only resolve Unity types when a language server sees a solution generated by Unity.

## Install the server

```bash
bash scripts/setup-csharp-lsp.sh          # cursor or code, whichever CLI is found; pass code|cursor to choose
```
It installs the `muhammad-sammy.csharp` extension (a C# extension that bundles OmniSharp and works in forks such as Cursor) and downloads OmniSharp 1.39.14 (net6.0 build) into the extension's folder for macOS/Linux, x64/arm64.
Restart the editor afterwards. On Windows install the extension from the Extensions view; it fetches OmniSharp itself. Alternative in stock VS Code: Microsoft's C# Dev Kit with the Unity extension (needs a licence under its terms).

## Make Unity produce the solution

1. Unity: `Edit > Preferences > External Tools`, choose your editor as External Script Editor, tick the project types to generate (embedded, local, registry packages as needed), **Regenerate project files**.
   This writes `<project>.sln` and the `.csproj` files at the project root.
2. In the code editor, open the **Unity project folder** (the folder with `Assets/`, or the repo root plus the setting below).
3. Monorepo, solution not at the workspace root: set `"dotnet.defaultSolution": "<relative path>/<project>.sln"` in the workspace settings.
4. Regenerate again after adding assemblies (asmdefs) or packages; stale solutions are the usual cause of "type not found".

## Check it works

Open a `.cs` file: hover over `MonoBehaviour` shows its doc, F12 on a project type jumps to the definition, the OmniSharp output channel shows the loaded solution. If not: wrong folder opened, solution missing or stale, or the language server crashed
(run "OmniSharp: Restart"). Keep `Library/`, `Temp/` and generated `*.csproj`/`*.sln` out of version control.
